4.5 Versions¶

Release plan (as of 2026-11-21)¶

This is a plan, not a promise; the CHANGELOG lists what each release actually contains.

Compatibility. Before 1.0, incompatible changes come with a new minor version. The incompatible changes of the 0.9 line are collected in 0.9.0. Releases 0.9.1 to 0.9.9 add features and fix bugs; code that works with 0.9.0 keeps working. One exception is announced here in advance: 0.9.10 turns the stricter behaviour that 0.9.x introduces as an option into the default, and removes what 0.9.x deprecated.

0.9.0 (next release) fixes since 0.8.17: environment-variable overrides take effect (a factory built the normal way ignored them); INI and YAML read and written as UTF-8; a malformed INI line rejects the file. values that fail schema validation are reported (WARNING and event) instead of being dropped silently, and no longer show up as "missing"; optional fail-fast, per schema entry or globally; validation of all entries at start-up. incompatible changes, once, with a migration guide: ConfigLocation becomes read-only and ConfigSource is removed; internal packages hidden by JPMS qualified exports; new module SPI (one module descriptor per module, storage providers and instances, secrets-provider interface), per-kind service files no longer read; deprecated setting names removed. Code that only uses ConfigFactoryBuilder, ConfigFactory, Configuration and ConfigEntry needs no changes beyond renamed settings. API stability marked in the Javadoc.

0.9.1 module settings handled the same way in every module; internal consolidation.

0.9.2 context facts: what mConfig finds out about its environment (host, zone, role). diagnostics: all entries for a key in priority order, where a write would go, fragments in location URIs.

0.9.3 multi-step bootstrap: a storage may take its own settings from another remote storage (for example a Vault token from a credential store, a ZooKeeper address from Vault), in a checked order.

0.9.4 run time: credential renewal and re-authentication, changes passed along the bootstrap chain, background retry of unavailable sources.

0.9.5 secrets, entry flags and POLICY: READ_ONLY / WRITE_ONLY enforced, secret sources failing closed, checks on POLICY locations, as options (default in 0.9.10). Secret values wiped on close in all layers.

0.9.6 schema format: specified, with an EDITION marker, aligned with JSON Schema; allowlist for schema sources; the CLI commands validate and propose-schema complete.

0.9.7 new sources: command-line arguments (picocli), .env files, one file per key; framework bridges; PKCS#11; Kubernetes RBAC role generator.

0.9.8, 0.9.9 reserved for additions as they become ready, such as the first secrets providers (OS credential stores) and encrypted values.

0.9.10 the stricter options from 0.9.x become the default; items deprecated in 0.9.x are removed. Then: preparation for the 1.0 API freeze.

Released versions¶

0.8.17 first public release since 0.8.13; includes the internal steps 0.8.14 to 0.8.16, which were not published on their own. new on Maven Central: Kubernetes storage modules (API and Fabric8). security: secret values never leave their own storage (saveTo(), CLI); Vault sends credentials only to a configured https address; Kubernetes tokens only over verified https; POLICY locations from the application need an explicit opt-in. self-configuration per component (.config/<company>/<app>/mconfig.properties), feature setting levels. Vault: KV version 2 reads, re-login on expired tokens; unavailable secret sources are reported (SOURCE_UNAVAILABLE). schemas without entries fail to load instead of loading empty. Jackson 3.2. See the CHANGELOG for the behaviour changes.

0.8.13 Jackson 3.x for the JSON, YAML and TOML modules; vulnerable dependencies replaced. first release with the Vault and AWS Secrets Manager modules on Maven Central.

0.8.12 smaller core: unified configuration leaf representation, simplified core API.

0.8.11 renamed mConfigFull to mConfigStandard, mConfigStandard to mConfigBasic, and mConfigBase to mConfigBasicBinary. new integration modules for HashiCorp Vault and AWS Secrets Manager.

0.8.5 comprehensive documentation overhaul and restructuring full comment preservation for TOML, INI, and (partial) YAML; separate TOML module write support via ConfigCursor updated examples and starters

0.8.0 public release on github and maven central formats: .properties, .json, .yaml, .toml, .ini sources: JAR, filesystem, environment variables, ZooKeeper, Windows registry dynamic configuration updates, config schemas, input validation, secrets, packaged in multiple modules, mConfigStandard and mConfigBasic as POM collections. .deb generated in mConfigTools, in addition to .jar. user-requested code smell pattern finds its place in mConfigCheese.

0.5.3 public release layered configurations, .properties format, raw files, OS-specific defaults, config schema basics. packaged as a single JAR. JPMS support.

0.4.2 first public release, 2018-03-29 released on maven central and metabit repository + website
